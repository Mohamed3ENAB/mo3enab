# خطة البناء — التذاكر بالترتيب

> **طريقة الشغل:** تذكرة واحدة في المرة. شغّل التطبيق بعد كل تذكرة. متخليش الـAI يكتب النظام كله مرة واحدة — هتاخد كود كتير مش شغال وهتقضي وقت أطول في إصلاحه.

---

## قبل التذكرة الأولى

- [ ] مستودع Git **خاص** (مش public — فيه تفاصيل تشغيل وأسعار)
- [ ] مشروع Supabase (أو PostgreSQL مُدار)
- [ ] بيئتين منفصلتين: تجريبية وإنتاج
- [ ] 🔴 `.gitignore` فيه `.env` — **قبل أول commit**

## برومبت البداية — انسخه أول ما تفتح المشروع

```
أنت مهندس منتج وبرمجيات. بتبني تطبيق ويب تقدمي (PWA) عربي RTL
لخدمة توصيل محلية في قرى مصرية.

قبل أي كود، اقرا الملفات دي في المستودع:
  delivery/README.md               ← القرارات المعتمدة والمخاطر
  delivery/01-spec.md              ← المواصفة وقواعد العمل
  delivery/02-pricing-economics.md ← التسعير
  delivery/db/schema.sql           ← قاعدة البيانات

التقنية: TypeScript + Next.js (App Router) + PostgreSQL عبر Supabase.
الأدوار: عميل · سائق · إدارة.

قواعد ملزمة:
1. الصلاحيات تتطبّق في قاعدة البيانات (RLS) مش في الواجهة بس.
2. مفيش أسرار إنتاج في الكود أو في المتصفح.
3. كل ميزة معاها ملف ترحيل (migration) واختبار صلاحيات.
4. الواجهة عربي RTL بالكامل، وتشتغل على موبايل أندرويد رخيص وإنترنت ضعيف.
5. ثمن البضاعة منفصل عن أجرة التوصيل في كل شاشة وجدول.

متكتبش النظام كله. اقرا الملفات، وبعدين اقترح **تذكرة رقم ١ بس**،
واذكر الملفات اللي هتنشئها أو تعدّلها، واستنى موافقتي.
```

```

اقرا delivery/01-spec.md قسم [القسم] وdelivery/db/schema.sql الأول.

المطلوب: [نسخة من عمود التذكرة]
معيار القبول: [نسخة من عمود معيار القبول]

قبل ما تكتب كود:
  ١. اعرض الملفات اللي هتنشئها أو تعدّلها.
  ٢. اعرض أي تغيير في قاعدة البيانات كملف ترحيل منفصل.
  ٣. اذكر اختبار الصلاحيات اللي هتكتبه.

بعد الكود: شغّل فحص النوع والاختبارات وبناء الإنتاج، وقوللي النتيجة الحقيقية.
لو حاجة فشلت، قول فشلت إيه — متقوليش خلصت وهي مش خالصة.
```

## قواعد الشغل مع الـAI

1. **تذكرة واحدة في المرة.** اطلب خطة قبل الكود.
2. **شغّل التطبيق بنفسك بعد كل تذكرة.** "الصفحة شكلها صح" مش اختبار.
3. 🔴 **راجع بنفسك أي كود في الفلوس أو الصلاحيات أو المستندات.** دي الحتت اللي غلطها بيكلّف.
4. 🔴 **متدّيش الـAI مفاتيح إنتاج ولا بيانات عملاء حقيقية.** بيانات وهمية في التطوير.
5. ألزمه بملف ترحيل + اختبار صلاحيات مع كل ميزة.
6. انشر على البيئة التجريبية واختبر بثلاث حسابات (عميل · سائق · إدارة) قبل الإنتاج.
7. لما يقول "خلصت"، اسأل: «إيه اللي اختبرته فعليًا؟» وشوف الإجابة.

## شروط دخول الميزات المؤجلة

متبنيش أي حاجة من دول قبل ما شرطها يتحقق:

| الميزة | الشرط |
|---|---|
| حسابات متاجر + قوائم | ٢٠ طلب/يوم **و** ٣ متاجر طلبت الميزة بنفسها |
| دفع إلكتروني | التسويات النقدية مستقرة شهر كامل بفرق = صفر |
| إسناد تلقائي ذكي | ٥٠ طلب/يوم (تحت كده الإسناد اليدوي أسرع وأدق) |
| تتبع GPS لحظي | العملاء طلبوه فعلاً — وراجع تكلفة الخرائط الأول |
| **تطبيق سائق أصلي (Flutter)** | إشعارات الـPWA وقعت طلبات فعليًا — ساعتها استخدم مهارات Flutter و Android اللي في الريبو |
| خدمة ركاب (توك توك) | 🔴 إجابة محامي مكتوبة + ترخيص + تأمين |
| تأجير سيارات | شريك مرخّص + عقود + نظام وديعة |
